为什么一个聊天框讲不清 Agent？

普通聊天框只让你看见答案，真正的 Agent 项目还要让人看懂路由、工具、证据、暂停和安全边界。

先记住结论：好的演示页面不是给 Agent 穿一件漂亮外套，而是把后端已经产生的可信证据排成一条看得懂的流水线。

控制台三块区域像什么

左侧 · 值班看板

告诉你 API、状态档案、退货库、Outbox 和审计库是不是都能工作。

中间 · 服务窗口

用户提交问题、查看答案和引用；需要退货时在这里等待审批。

右侧 · 流水线灯板

按顺序显示认证、分类、检索、规划、工具和响应等公开业务事件。

右侧时间线是不是模型思维链

不是。它展示的是开发者主动定义的业务事件，例如 身份已验证、订单工具查询成功。 模型隐藏的逐字推理不会出现在页面里。面试时应使用“可审计执行轨迹”这个说法，而不是“暴露思维链”。

用户：查询订单 SO100001
  ↓ JWT sub 绑定 user-001
  ↓ 分类为 order_status
  ↓ 规划器选择 get_order_status
  ↓ 工具再次检查订单归属
  ↓ 观察到“已发货”
  ↓ 生成用户回答

为什么现在要粘贴四枚 Token

身份能做什么不能做什么
普通用户提交售后对话不能批准退货或读审计
审批人批准/拒绝退货草案不能冒充用户查询订单
审计员验证审批哈希链不能批准自己的操作
开发调试读取脱敏 Checkpoint 回放不能调用业务、审批或审计接口
别为了“一键演示”打安全折扣：如果身份下拉框可以直接获得所有高权限 Token，项目就多了一个认证后门。当前 Token 只在网页内存里，刷新即消失。

打开控制台

docker compose up --detach --build --wait --wait-timeout 120
uv run python examples/09_generate_dev_tokens.py

浏览器打开：http://127.0.0.1:8000/

面试时怎么说

可直接回答：“我没有另做一套假演示数据。控制台直接调用现有JWT保护的chat、approval、audit和development debug接口，并读取health/readiness。快速时间线来自公开events；教学模式通过aget_state_history读取脱敏StateSnapshot并计算字段差异，不推断模型思维链。退货只有真实返回LangGraph interrupt才出现审批卡，恢复使用原thread_id。四类Token只存在页面内存，动态文本全部用textContent，并通过同源CSP限制脚本、样式和网络连接。”

当前求职阶段要会演示四条主线和解释安全取舍，不需要深入学习复杂前端框架。
