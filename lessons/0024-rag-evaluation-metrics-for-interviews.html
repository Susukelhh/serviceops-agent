RAG 评价指标：面试够用版

第24课 · 不背一串缩写，而是判断问题出在“找资料、排资料、答问题，还是系统运行”。

先记住总图：检索指标回答“资料找得对不对”；生成指标回答“模型有没有根据资料正确作答”；业务与工程指标回答“该拒答时能否拒答，以及线上是否又快、又稳、成本可控”。

一、四层指标

1. 找没找到

Recall@K / Hit@K：正确资料有没有进入前 K。适合诊断漏召回。

Precision@K：前 K 里有多少真相关。适合诊断上下文噪声。

2. 排得靠不靠前

Top-1：第一名是否正确。

MRR@K：只看首个相关结果的名次；第一名得1，第二名得0.5。

nDCG@K：同时考虑多个相关结果和位置，越靠前贡献越大。

3. 答得是否可信

Answer Correctness：答案与人工参考答案是否一致。

Faithfulness / Groundedness：答案中的主张能否由检索证据支持。

Answer Relevance：是否真正回答用户问题。

Citation Validity：引用是否存在、合法并来自本轮证据。

4. 能否安全上线

FPR：本不该检索或回答的问题，被错误放行的比例。

Abstention Accuracy：知识不足时正确拒答的比例。

Unsupported Answer Rate：无充分证据却仍回答的比例。

P95、错误率、Token/费用：大多数用户之外的慢请求、稳定性和成本。

二、项目中的真实口径

指标项目如何计算面试时怎么解释
Recall@K正例问题中，Top-K 至少出现一个期望文档的比例这是问题级命中率，严格说接近 Hit@K；不是逐文档的传统 Recall
Top-1正例中首个结果就是期望文档的比例比 Recall@5 更能反映送入生成器的首条证据质量
MRR@K全部正例的首个相关排名倒数均值适合比较 Rerank 前后是否把正确资料前移
nDCG@K对所有已标注相关文档按排名折损，再与理想排名归一化适合存在多个相关文档的查询
Decision Accuracy / FPR正例命中与负例拒绝共同计分；负例有任意结果即误召回防止靠降低阈值、什么都召回来制造高 Recall
Answerable Recall / Abstention有答案时是否回答；无答案时是否拒答防止“全部拒答”制造虚假安全
Unsupported / Citation知识缺口是否被乱答；引用ID是否属于本轮候选白名单这是项目的可执行幻觉控制口径

三、我们的实验真正说明了什么

实验关键结果结论
旧 RAG 基线Recall@5 100%，Top-1 87.5%，MRR 93.1%，FPR 100%会找资料，但对域外问题什么都找，不能上线
范围门锁定集 Recall 100%，Decision 100%，FPR 0%把“是否该检索”与“检索什么”拆开是有效优化
候选内 BM25 重排Top-1 90%→100%，MRR 95%→100%，Recall 保持100%证明改善的是排序，不是召回
千问语义向量锁定正例 Recall/Top-1 100%，但 FPR 50%语义更强不等于整体可晋级
Qdrant+BM25+RRF锁定 Recall 100%，Top-1 91.67%，MRR 95.83%，FPR 50%完整混合召回已实现，但冻结候选未通过质量门
端到端 Grounded RAGAnswerable 100%，Abstention 100%，Unsupported 0%，Citation 100%在12条一次性锁定题上通过；样本小，不能冒充线上普遍效果

四、面试官最关心的不是公式

  1. 你的标签怎么来的？按文档还是 Chunk 标注？一题可有几个相关来源？
  2. 为什么选 K=5？K 增大后 Recall、噪声、Token 和延迟怎么变化？
  3. 为什么 Recall 100% 仍可能很差？能否同时给出 Top-1、FPR 和端到端结果？
  4. Rerank 到底提高了什么？正确文档没进入候选集时，它能不能救回来？
  5. 开发集与锁定集如何隔离？有没有反复看 holdout 调参造成数据泄漏？
  6. 幻觉如何衡量？LLM-as-judge 是否与人工抽检校准？失败样本如何回流？
  7. 离线分数上线后如何监控：人工转接率、一次解决率、用户反馈、延迟和成本？
30秒自测

如果 Recall@5 从100%保持100%，Top-1从90%升到100%，你能说“召回率提高了”吗？

答案：不能。只能说排序质量改善；Recall 没变。还要检查负例FPR、端到端无依据回答率、延迟与成本。
