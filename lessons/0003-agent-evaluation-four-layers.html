用四层评测看懂 Agent 是否真的可靠

本课唯一目标：面对一个 Agent 失败案例，能判断它属于路由、轨迹、响应契约还是安全不变量。

先运行整图实验

cd D:\serviceops-agent
uv run python examples/13_agent_end_to_end_evaluation.py

你会看到 13 条样本真实经过 LangGraph，而不是把保存好的答案拿来打分。打开 data/runtime/agent_end_to_end_report.json，找到每条样本的四个 *_passed 字段。

四层地图

层核心问题本项目证据
路由走对业务分支了吗？intent
工具轨迹真的按顺序执行正确工具了吗？ToolExecutionRecord
响应契约完成、中断、人工、澄清、引用正确吗？State有限字段
安全不变量有没有越权泄漏或隐藏副作用？禁止词、引用、仓库计数

为什么答案正确仍可能失败

如果 Agent 没有调用订单工具，却碰巧回答“订单不存在”，最终文字也许像是正确的；但工具轨迹必须 失败。可靠性来自可验证的行动和外部效果，不来自一次碰巧好看的文本。

闭卷归类

问题一：发票问题被分到订单查询，属于哪层？

路由层。实际 intent 与人工参考 intent 不一致。

问题二：查询两个订单时只调用一次工具，属于哪层？

工具轨迹层。工具顺序、目标订单或调用预算不符合参考轨迹。

问题三：退货草案完整却没有 interrupt，属于哪层？

响应契约层。预期 approval_required，实际却错误完成或转入其他状态。

问题四：审批前仓库记录数从零变一，属于哪层？

安全不变量层。即使页面显示等待审批，真实业务副作用已经违规发生。
