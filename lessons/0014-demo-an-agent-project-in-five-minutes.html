SERVICEOPS AGENT · LESSON 14

五分钟讲清一个企业 Agent 项目

你的目标不是在五分钟内证明自己记住了全部框架，而是让面试官清楚看到：你解决了什么问题、系统如何控制风险、证据在哪里，以及你知道哪些事情还没做到。

与你的求职任务直接相关

近期杭州 Agent 应用岗位更看重“能落地、能排错、能解释取舍”。因此演示重点是可运行证据，不是把 LangChain、LangGraph 名词全部念一遍。

生活类比：项目演示像电影预告片

预告片不会把两小时电影逐帧播放，而会选出最能说明冲突、能力和结局的片段。项目演示也一样：订单工具证明行动能力，RAG 证明证据边界，越权场景证明安全，人工审批证明可控写入。

记住这一条表达公式

业务问题 → Agent 决策 → 确定性执行 → 安全边界 → 可验证证据

五分钟只演示四段

0:00—1:40
订单工具 + Checkpoint证明模型不能直接查库；规划、白名单、身份绑定、工具观察和状态恢复彼此分开。
1:40—2:30
有据 RAG证明回答必须带已发布公共证据；无证据、低分或非法引用会安全降级。
2:30—3:15
跨用户信息隐藏证明 JWT sub 才是可信身份，用户文本不能覆盖工具查询条件。
3:15—5:00
人工审批 + 工程证据证明 interrupt 前零写入、批准后恢复原线程，同时诚实说明本机 Docker 不等于完整生产平台。

三个必须能脱稿回答的问题

1. 为什么这里必须用状态图？先自己回答，再展开。

因为流程不只是 A→B→C：订单路径存在工具循环，退货路径需要暂停、人工输入和跨进程恢复。显式 State、条件边和 Checkpoint 让这些行为可测试、可回放。

2. Checkpoint 和业务表分别保存什么？

Checkpoint 保存 Agent 做到哪里；业务表保存现实业务已经发生什么。暂停等待审批时可以只有 Checkpoint，没有退货记录。

3. 为什么不展示模型隐藏思维原文？

它不是稳定审计证据，还可能泄漏提示词和内部信息。项目展示结构化决策、路由原因、工具计划、引用和状态变化。
