SERVICEOPS AGENT · LESSON 25

FAQ不是“一搜一答”，而是连续过门

目标：能沿着真实代码讲清每一关的输入、判断、输出，以及为什么失败时统一转人工。

生活类比：企业资料室

先由前台判断来访者要办什么；门卫检查是否属于公开售后业务；两位图书管理员分别按“意思相近”和“字词精确”找资料；主管合并两张书单；答复员判断资料是否真的包含答案；档案员核对每个出处。任何一关没把握，都不让答复员凭记忆发挥。

1

意图分类

把请求限制为 FAQ、订单查询、退货申请、人工接管四类。置信度低于 0.85 或分类服务失败，转人工。

2

业务范围门

在 Embedding 前拒绝空问题、天气/投资/医疗/代写、旧政策索取，以及凭据或内部规则探测。拒绝后不调用检索。

3

双路独立召回

Qdrant 从整座 Collection 找语义近邻；BM25 从完整切片语料找词面命中。默认各取 8 条，不相互依赖。

4

RRF融合

按 chunk_id 去重，使用两张榜的名次计算融合分，最终只保留 Top 3。

5

检索证据门

Qdrant 先过滤低于 0.10 的向量命中；融合结果非空才放行。回答节点实际只取前 2 条控制噪声。

6

生成充分性门

生成器返回结构化的 answer、citation_ids、is_answerable。若证据不蕴含答案，应主动拒答。

7

引用白名单

代码要求至少一个引用，且每个 ID 都必须属于本轮候选；模型不能靠自己声明“引用合法”。

8

回答或人工

只有 grounded 标记、非空答案、合法引用同时存在才能结束；否则统一进入人工节点并覆盖不可靠草稿。

RRF到底算什么

RRF(d) = 1.0 / (60 + dense_rank) + 0.8 / (60 + lexical_rank)

某通道没召回该切片，就没有该通道的加分。RRF使用名次而不是直接相加余弦分数与BM25分数，因为两种原始分数不在同一量纲。

三个容易混淆的“证据判断”

判断它回答的问题项目实现失败去向
相关性有没有看起来相关的候选？Qdrant阈值、BM25词面命中、RRF排序、非空候选人工
充分性候选正文是否真的包含所问事实？生成器的结构化 is_answerable人工
合法性答案声明的出处是否来自本轮候选？Python集合白名单校验引用ID人工

Compose 默认使用哈希向量、模拟意图分类和抽取式回答。抽取式回答只要收到证据就把 is_answerable 设为 true，因此它适合零费用、可重复演示，却不能替代真实模型的语义充分性判断。切换到 LLM 生成后端时，才由受约束模型判断证据是否蕴含答案；无论哪种后端，引用白名单仍由确定性代码执行。

为什么意图分类后还需要业务范围门？

分类器是概率判断，可能被混合表达或关键词干扰。范围门覆盖少量企业明确禁止的高置信规则，而且放在 Embedding 前，可以避免域外或敏感请求产生调用费用和错误证据。两者是纵深防御，不是重复劳动。

为什么不能把 Qdrant 分数和 BM25 分数直接相加？

余弦相似度与 BM25 分数的尺度、分布不同，直接相加会让某一路因数值范围而天然占优。RRF只看相对名次，更容易稳定组合异构检索器。

引用是真实ID，为什么仍可能是幻觉？

真实ID只证明文档存在且本轮被召回，不证明正文包含答案。所以必须把充分性判断放在引用合法性判断之前理解。
