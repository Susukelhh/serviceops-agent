跟踪一条请求穿过 StateGraph

先运行

cd D:\serviceops-agent

再跟踪真实工单

输入“我的订单到哪了”后，共享状态先由 normalize_request 增加 normalized_message，随后 classify_intent 增加 intent=order_status。条件边读取该意图并选择 answer_order。

三个节点每次都返回一个新的 events 列表，但最终列表仍包含全部事件， 因为该字段声明了 operator.add Reducer。

闭卷回忆

不要先展开答案，尝试用自己的话回答：

问题一：State 和 Node 分别负责什么？

State 携带任务数据；Node 读取状态并返回本步骤产生的更新。

问题二：为什么 events 不会被覆盖？

它通过 Annotated 绑定了 operator.add Reducer，多次更新会执行列表相加。

问题三：未知问题为什么转人工？

证据不足时选择安全退出，避免自动系统猜测并产生错误业务动作。
