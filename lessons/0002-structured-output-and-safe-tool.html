结构化分类与安全工具边界

本课唯一目标：解释为什么模型能提供订单号，却不能提供当前用户身份。

先运行工具

cd D:\serviceops-agent
uv run python examples/02_order_tool.py

第一段输出是模型可见的工具Schema。它应该只有order_id，没有 user_id。身份由系统创建工具时通过闭包注入。

再理解两种结构化

模型结构化输出：Pydantic约束模型只能给出意图、置信度和简短原因。

工具结构化输入/输出：Pydantic校验订单号格式，OrderLookupResult校验查询事实。

两者解决不同问题：前者约束模型决策，后者保护业务系统边界。

闭卷回忆

为什么不让模型填写user_id？

因为用户文本和模型输出都不可信；身份必须来自认证系统，否则模型可伪造身份越权查询。

为什么低置信度FAQ仍可能转人工？

模型输出只是候选决策，系统阈值是独立安全门，低把握结果不能进入自动路径。

为什么工具结果还要再次校验？

工具也可能出错或被替换；结构化校验防止异常字段继续污染状态和用户回答。
