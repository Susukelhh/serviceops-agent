Agent 容器部署速查表

ServiceOps Agent · 面试前 2 分钟复习 / 构建前检查 / 可打印

构建可复现

  • Python tag + digest 固定
  • uv 版本固定，uv.lock 严格同步
  • 依赖层先复制，源码层后复制
  • 项目以 --no-editable 安装
  • builder 工具不进入 runtime

构建上下文

  • 排除 .env 与所有本机密钥
  • 排除 .venv、IDE 和缓存
  • 排除 SQLite/WAL/评测报告
  • 只复制运行依赖与 data/seed
  • Secret 在运行时注入，不写镜像层

运行最小权限

  • 固定 USER 10001:10001
  • 根文件系统只读
  • Capability 全删除
  • no-new-privileges
  • PID / CPU / 内存边界

状态与进程

  • data/seed 镜像内只读
  • data/runtime 具名卷可写
  • 一个容器一个 Uvicorn worker
  • SIGTERM + lifespan 优雅关闭
  • 多副本前迁移 PostgreSQL

三层部署冒烟

层检查失败说明
LivenessGET /health = 200/okWeb 进程没有正常服务
ReadinessGET /ready = 200 且四依赖 ready进程活着但不能接业务流量
Security无 JWT 的 chat 必须 401部署配置绕过了应用认证

安装 Docker 后的最短命令

  1. docker compose config
  2. docker compose up --build --detach
  3. uv run python examples/15_container_smoke_test.py
  4. docker compose logs --tail 100 serviceops-agent
  5. docker compose down（默认保留数据卷）
面试一句话：我用锁文件和 digest 构建多阶段镜像，最终进程以非 root、只读根目录和单 worker 运行；平台根据真实 readiness 分流，SQLite 只作为单机演练状态层。
不能夸大的边界：容器能启动 ≠ 已生产可用；当前尚缺 PostgreSQL 多副本、企业 OIDC、TLS/限流、备份恢复、镜像扫描与容量压测证据。
参考：Docker multi-stage/build best practices、FastAPI Docker deployment、uv Docker integration。镜像摘要会随受控依赖升级更新。
