退货写流程安全速查卡

把“流程恢复、业务幂等、可靠投递、审计证据”四件事分开说。

thread_id

定位同一条 LangGraph Checkpoint，回答“从哪里恢复”。

idempotency_key

跨重试定位同一业务写入，回答“是否已经创建过”。

Outbox event_id

按线程稳定标识一次完成事实，回答“这条事件是否投递过”。

存储保存什么不等于什么
CheckpointState、interrupt、下一节点业务退货记录
return_requests申请号、用户、订单、原因、状态、幂等键审批证据链
return_outbox_events待投递完成事实、摘要、投递状态第二份业务主表
approval_audit_events决定/终态、主体、摘要、链位置和哈希不可推翻的数字签名

业务写事务

LOCK(idempotency_key)
→ 同键同负载：返回原 RR 编号
→ 同键不同负载：conflict，零覆盖
→ 新键：复查订单资格
→ INSERT return_requests
→ INSERT return_outbox_events(pending)
→ 两项一起 COMMIT / 一项失败一起 ROLLBACK

哈希链

first.previous = "0" × 64
event_hash = SHA256(canonical_json(event_without_event_hash))
next.previous = current.event_hash

能检测：字段修改、中间删除、换序、错误前驱。 不能单独证明：链尾未被删除、整库未被管理员重写、事件具有法律意义上的不可抵赖性。

面试表达：传输至少一次，消费者幂等，获得业务效果上的一次；哈希链是可检测篡改，不是绝对防篡改。
