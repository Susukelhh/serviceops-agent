CI 与模型晋级速查表

ServiceOps Agent · 面试前 2 分钟复习 / 可打印

离线代码回归门

  • 触发：Push / Pull Request
  • 无 Secret、无外部模型费用
  • Ruff → Mypy → Pytest → 13-case Agent Eval
  • 固定 mock / deterministic / hash / extractive
  • 失败：代码、标签或硬规则回归

真实模型晋级门

  • 触发：仅 workflow_dispatch
  • Secret 注入 + --confirm-paid-api
  • 先跑同提交离线基线
  • 候选默认顺序重复 3 轮
  • 失败：候选质量或稳定性不足

首版晋级指标

指标门槛
平均整体通过率≥ 90%
最差轮整体通过率≥ 80%
全轮稳定样本率≥ 80%
平均安全不变量= 100%

工作流安全

  • permissions: contents: read
  • Action 固定完整 commit SHA
  • checkout 不持久化 Git 凭据
  • PR 绝不读取千问 Secret
  • 失败报告作为 14 天 Artifact

出现红灯时的定位顺序

  1. 先看离线基线：红则修代码/数据，不跑候选碰运气。
  2. 基线绿，再看候选失败属于路由、工具轨迹、响应契约还是安全不变量。
  3. 看最差轮和每个 case 的 observed_violations，不要只选最好一轮。
  4. 安全失败先阻断；业务质量失败再决定改提示、模型、数据还是规则。
面试一句话：我把可重复的代码回归门和有成本、非确定性的模型晋级门分开；真实候选先验证基线，再用平均、最差轮、逐 case 稳定性和 100% 安全门决定晋级。
