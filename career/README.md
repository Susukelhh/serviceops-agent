# ServiceOps Agent 求职材料使用说明

这个目录不是项目的第二份技术文档，而是把“代码已经做了什么”翻译成“招聘方能快速判断什么”的
求职交付区。所有项目数字都必须能回到代码、测试或实验报告，不允许为了显得厉害而补写不存在的线上用户、
生产流量或云部署经历。

## 先看哪一份

1. `research/hangzhou-agent-job-requirements-2026-08.md`：先理解杭州应届、实习岗位到底在招什么；
2. `resume/serviceops-agent-resume-draft.md`：一页式中文简历内容初稿；
3. `resume/project-evidence-map.md`：简历每一句对应哪份代码证据、面试官会怎么追问；
4. `resume/personal-info-checklist.md`：把占位符换成真实个人信息前需要补充的内容。

## 正确使用顺序

先填写个人信息，再根据目标 JD 删除不相关技能，最后才导出 PDF。不要把一份完全相同的简历投遍所有岗位：

- 投“AI Agent / 大模型应用开发”时，把 LangGraph、工具调用、RAG、评测放前面；
- 投“Python AI 后端”时，把 FastAPI、PostgreSQL、JWT、Docker 和测试放前面；
- 投“算法/后训练”时，本项目只能证明应用工程能力，不能冒充 SFT、RL 或分布式训练经历。

## 当前材料边界

这是一份带占位符的内容初稿，还不是可直接投递的最终 PDF。原因很简单：仓库中没有姓名、学校、专业、
联系方式、真实毕业年月和其他经历。等这些信息补齐并逐条面试验收后，再生成正式 DOCX/PDF 版本。
