# 第 24 步：先让旧 RAG 在困难集上暴露问题

## 本步解决的问题

旧版 RAG 的 11 条评测全部通过，但语料只有 4 份可索引短文、实际 4 个 Chunk；问题与政策关键词也很接近。
这个 100% 可以证明代码没有明显回归，却不足以证明检索方案经过真实优化。本步不急着加入 Rerank、混合检索或
新 Embedding，而是先建立可复现的困难基线，回答三个问题：旧方案错在哪里、后续为何引入某项技术、改进是否能量化。

## 现实问题 → 实验设计

| 现实问题 | 本步设计 | 要观察的指标 |
|---|---|---|
| 相邻政策容易混淆 | 普通退货/定制退货、普通发票/红冲、物流延迟/签收未收到成对出现 | Top-1、MRR、nDCG |
| 用户不按政策原文提问 | 加入口语、同义改写、跨段组合问题 | Recall@5 |
| 降低阈值会什么都敢搜 | 加入带“退货、保修、发票”等词的天气、股票、医疗、代写负例 | 负例误召回率 |
| 内部和失效规则可能泄漏 | 同一语料文件加入 internal/draft 与 retired 文档 | 检索结果中是否出现敏感 ID |
| 反复看测试题会过拟合 | 开发集与锁定集分文件；本阶段只运行开发集 | holdout 只报告数量 |
| 切片参数以前没有真正生效 | 12 份长文使用 500 字窗口与 80 字重叠生成 23 个 Chunk | 实际 Chunk 数 |

## 固定 Baseline

- Embedding：本地确定性 Hash Embedding，1024 维；
- 向量库：Qdrant 内存模式；
- Chunk：500 字符，Overlap 80 字符；
- 检索：Top-K = 5，Score Threshold = 0.10；
- 语料：14 份原始文档，其中 12 份 `published + public` 可索引；
- 数据：32 条开发样本，12 条锁定样本；
- 费用：不读取千问模型开关，不调用任何付费 API。

版本化契约位于 `data/evaluation/rag_v2_baseline_experiment.json`。如果语料、人工标签、参数或判定规则变化，
必须修改版本，不能用旧报告冒充同一次实验。

## 第一次有效结果

| 指标 | Hash Baseline v2.0.0 |
|---|---:|
| Recall@5 | 100.0% |
| MRR@5 | 93.1% |
| Top-1 准确率 | 87.5% |
| nDCG@5 | 94.8% |
| 负例误召回率 | 100.0% |
| 决策失败 | 8 / 32 |
| 排序优化机会 | 3 / 32 |

这组结果不能被描述成“RAG 整体准确率 100%”。它说明 Top-5 召回没有漏掉正例，但所有 8 条负例都错误返回了证据，
而且 3 条正例的正确政策没有排第一。最突出的问题不是先追求更高 Recall，而是先减少域外误召回，并改善相邻政策排序。

## 根因假设与后续最小实验

1. **负例误召回**：当前 Hash 向量依赖中文单字/双字词面重合，0.10 阈值很低；带有业务词的域外问题容易越过门槛。
   下一步先做阈值扫描与域内意图门，不直接用昂贵模型掩盖路由问题。
2. **口语与同义表达**：Hash 不能真正理解“票已经出了”“手里没有包裹”等语义。阈值方案稳定后，再以真实 Embedding
   作为单变量候选，并明确 API 费用。
3. **相邻政策排序**：Top-5 已经包含正确文档但排位靠后，才是 Rerank 的合理使用场景。先保存候选，再比较无重排、
   轻量规则重排和模型 Rerank 的 Top-1/MRR 提升与延迟代价。
4. **Chunk 与检索方式**：后续在开发集比较窗口、重叠及 BM25 + 向量混合召回；只有某类失败确实改善才保留技术。

所有候选确定后，锁定参数并只运行一次 holdout。若 holdout 没有同步改善，应回到开发集重新分析，不能继续针对
holdout 改到满分。

## 如何运行

在 PyCharm 中创建 Python 运行配置：

- Script path：`D:\serviceops-agent\examples\24_rag_problem_baseline.py`
- Working directory：`D:\serviceops-agent`
- Parameters：留空
- Environment variables：`PYTHONUTF8=1`
- Interpreter：`D:\serviceops-agent\.venv\Scripts\python.exe`

也可以在项目终端运行：

```powershell
uv run python examples/24_rag_problem_baseline.py
```

退出码 0 表示“困难集规模达标且旧方案成功暴露失败”，不是表示 Baseline 可以上线。详细结果写入
`data/runtime/rag_v2_problem_baseline_report.json`。

## 本步边界

- 尚未实现 BM25、RRF、Rerank 或新 Embedding；本步只建立引入它们的证据基础。
- 语料仍是为项目构建的受控企业售后样本，不冒充真实公司线上数据。
- 当前指标是本地离线开发集结果，不代表线上用户分布。
- 锁定集本阶段没有运行，避免边做候选边偷看最终答案。
