# 第一步：建立可运行的状态图骨架

## 本步目标

在没有模型密钥和数据库的情况下，跑通一条完整工单请求，并为后续能力建立稳定边界。

## 已实现

1. 用 `uv` 与 `pyproject.toml` 管理 Python 3.12 和依赖。
2. 用 `TypedDict` 定义 LangGraph 共享状态。
3. 用普通 Python 函数实现输入规范化、分类和响应节点。
4. 用条件边把三种意图路由到不同节点。
5. 用 Reducer 累积每个节点产生的执行事件。
6. 用 FastAPI 暴露健康检查和对话接口。
7. 用 pytest 分别测试节点、路由、整张图和 HTTP API。
8. 提供 PyCharm 解释器、运行配置、pytest 和 UTF-8 设置指南。
9. 按教学级规范补充中文注释，逐字段解释 State/Schema，逐段解释图控制流和测试断言。

## 验证结果

- Python：`3.12.13`
- Ruff：检查通过，全部 Python 文件格式一致
- Mypy：严格模式检查通过
- Pytest：`12 passed`
- 真实 HTTP：健康检查与订单请求均返回 `200 OK`

PyCharm 操作步骤见 [`../pycharm.md`](../pycharm.md)。
详细注释规范见 [`../code-commenting-convention.md`](../code-commenting-convention.md)。

## 为什么第一版不用真实大模型

如果一开始同时引入模型、数据库、向量检索和外部接口，测试失败时很难判断问题来自哪里。
确定性分类器让控制流可以重复执行，也是后续评测模型分类效果时必须保留的基线。

## 面试可回答的问题

- 条件边如何决定下一跳？
- 为什么未知请求默认转人工？
- 为什么 API 层不直接写业务逻辑？
