# 第37步：不要继续调Prompt，先修评测器和范围门

## 从13/30到29/30为什么不是“刷分”

第36步首次自动盲测13/30必须永久保留。随后付费REGRESSION保存了原问题、模型答案、实际证据和逐事实
匹配，人工逐题审计发现：自动失败不等于模型答错。

REGRESSION自动评分为15/30，而人工语义复核为29/30。二者差异来自：

- 6道正确同义表达被机械短语或词序规则漏判；
- 5道金标要求回答用户没有询问的背景事实；
- 1道同时存在上述两类问题；
- 1道正确拒答的草稿引用没有按生产最终状态清空；
- 1道本可用公开政策回答的问题被错误标成必须完全拒答；
- 真正剩余的1道端到端错误，是范围门把安全咨询误判成凭据提取。

29/30是**已揭晓回答的人工审计**，不是自动Gate，也不是新盲测。它不能覆盖13/30，但能决定接下来应该
修哪里：当前没有证据支持继续修改Prompt v2，优先级应转向范围门与评测有效性。

## 范围门v2解决什么问题

第一版规则看到“提供+密码/验证码”就倾向拦截。下面的问题因此被误拒：

```text
客服可以让我提供账号密码或短信验证码来核验吗？
```

用户并不是索取验证码，而是在询问客服行为是否安全。范围门v2增加窄范围安全咨询识别：

- 同时出现客服/官方/维修人员、索要或提供语境、密码或验证码时，可以进入公开安全知识检索；
- “验证码是多少”“直接告诉我密码”等明确索密请求仍然拒绝；
- 同一句既有安全咨询又有直接索密时，直接索密优先拒绝；
- 天气、投资、医疗、内部政策和其他v1规则完全保持不变。

v1类继续保留用于复现第25至36步历史结果；v2作为新候选，通过配置字段
`query_policy: deterministic_v2`显式选择。当前生产默认仍是v1，必须在下一套新密封集通过后才能晋级。

## 最终用户状态评分

生产FAQ节点在 `is_answerable=false` 时会清空引用，再向用户拒答或转人工。旧评测器却直接检查模型草稿，
把“正确拒答但草稿带证据”判成失败。

新配置字段 `sanitize_declined_citations` 允许未来实验显式选择生产最终状态口径：

- `false`：保留第34至36步历史行为和已发布指纹；
- `true`：拒答时只在评分视图清空引用，私有诊断仍保留原始草稿，便于审计。

该字段只有为 `true` 时才进入新候选指纹，因此历史候选指纹没有变化。

## 这一步得到的工程结论

1. RAG评测不能只看引用是否合法，还要检查答案事实是否完整；
2. 事实评分也不能堆叠过度严格的背景要求，否则会把简洁正确答案判错；
3. 关键词安全门必须区分“请求秘密”和“咨询秘密是否应该提供”；
4. 端到端指标要评分用户最终看到的状态，而不是中间草稿；
5. 人工审计可以诊断指标，但不能替代下一次未知样本验证。

## 下一步

下一套密封集必须在揭晓前完成以下冻结：

- 使用范围门 `deterministic_v2`；
- 使用 `sanitize_declined_citations=true`；
- 关键事实只覆盖用户明确问题，不强制无关背景；
- 否定、条件、词序和数值变体在出题阶段做对抗性单元测试；
- Prompt仍保持v2，先单变量验证范围门与评分修复，而不是同时改模型提示。
