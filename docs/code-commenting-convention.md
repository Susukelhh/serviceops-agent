# 教学级中文代码注释规范

这份规范适用于 ServiceOps Agent 后续新增和修改的全部 Python 代码。目标是让正在学习
LangGraph 和企业 Agent 开发的人，在 PyCharm 中沿着代码即可理解数据如何流动以及为什么
采用当前设计。

## 一、模块注释

每个 Python 文件顶部说明：

- 文件在项目中的职责；
- 它位于调用链的哪一层；
- 它明确不负责什么，避免职责边界模糊。

## 二、数据字段注释

State、Pydantic Schema、配置类和枚举的每个字段都必须解释：

1. 字段表示什么业务含义；
2. 字段由哪个入口或节点写入；
3. 哪个节点、接口或系统会读取它；
4. 缺失、默认值或错误值有什么影响；
5. 涉及 Reducer 时说明具体合并规则。

示例：

```python
# API 层为每次请求生成的唯一标识；贯穿整张图，后续用于日志、追踪和故障定位。
request_id: str

# 执行事件列表；每个节点只追加自己的事件，add Reducer 确保旧事件不会被覆盖。
events: Annotated[list[str], add]
```

## 三、控制流注释

对节点注册、普通边、条件边、`if` 分支、循环、重试和异常处理分别解释：

- 为什么执行这个判断；
- 条件成立后会走向哪里；
- 默认或异常路径为什么安全；
- 是否会产生数据库、网络或外部工具副作用。

## 四、函数内部注释

每段关键语句说明输入、处理和输出。注释重点解释设计意图，不只把 Python 语法翻译成中文。
字典返回值中的每个业务字段都单独说明其含义和下游用途。

## 五、测试注释

测试代码使用 Arrange/Act/Assert 或 Given/When/Then 思路：

- 为什么构造当前输入；
- 这次调用覆盖哪条路径；
- 每个断言能够防止什么回归。

## 六、维护要求

代码行为变化时必须同步更新邻近注释。过期注释比没有注释更危险，因此 Ruff、Mypy、pytest
检查之外，代码审查还要确认注释与实际执行路径一致。
