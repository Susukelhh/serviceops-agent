12. 评测：不是看一次演示成功就算完成
====================================================================================================

为什么 Agent 不能只测最终答案
====================================================================================================

最终一句话看起来正确，不代表过程安全。例如模型可能查错用户的订单，又碰巧生成了正确状态；也可能在审批前偷偷写库。
所以项目把评测拆成四层：

1. **路由**：意图和路线是否正确；
2. **轨迹**：应该调用的工具是否调用、顺序是否符合要求；
3. **响应契约**：答案、引用、审批状态等字段是否正确；
4. **安全不变量**：是否越权、审批前是否零写入、内部知识是否泄露。

Agent 回归集
====================================================================================================

13 条版本化用例覆盖 FAQ、订单、未知意图、工具异常和退货审批等路径。
离线确定性基线为 13/13；``qwen-plus`` 候选 1.1.0 连续三轮每轮 13/13，安全不变量准确率 100%。

这只能说明 13 条小型黄金集稳定通过，不能写成线上全量准确率 100%。

RAG 为什么分开发集和锁定集
====================================================================================================

开发集像平时练习题，可以观察失败并调参数；锁定集像期末卷，参数冻结后只看一次。
如果看完锁定集答案又修改规则，它就已经变成新的开发集，不能继续声称是未知数据验证。

指标的大白话解释
====================================================================================================

* **Recall@5**：正确资料有没有进入前五名候选。
* **Top-1**：排第一的是否就是正确资料。
* **MRR**：正确资料总体排得有多靠前。
* **FPR**：本不该回答的问题，有多少被误放行。
* **无依据回答率**：知识缺口问题中，有多少仍被系统编出答案。
* **引用合法率**：引用是否真的来自本次允许的证据集合。

自动化质量门
====================================================================================================

* Ruff 检查常见代码问题和导入规则；
* Mypy 严格检查类型边界；
* Pytest 会覆盖四路检索装配、参数选择和holdout默认隔离；
* GitHub Actions 在 Linux 上重跑离线门禁和 13 条 Agent 评测；
* 真实千问实验必须手工确认，不在普通 PR 中消耗费用。
