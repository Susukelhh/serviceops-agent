13. Docker 与交付：把运行环境一起装箱
====================================================================================================

镜像和容器
====================================================================================================

Docker 镜像像封好的软件安装包，包含代码、Python 依赖和启动命令；容器是这个包真正运行起来的实例。
镜像本身不会让互联网用户自动访问项目。要让别人访问，仍需要把容器运行在可达的服务器上，并配置域名、HTTPS 和安全策略。

Compose 中有哪些服务
====================================================================================================

.. code-block:: text

   Windows 浏览器
        │ 127.0.0.1:8000
        ▼
      Nginx gateway
        ├──────────────┐
        ▼              ▼
     agent-a         agent-b
        └──────┬───────┘
          ┌────┴────┐
          ▼         ▼
     PostgreSQL   Qdrant

   migrate：数据库启动后先升级表结构，成功退出
   index-knowledge：Qdrant健康后只初始化一次共享索引，成功退出

只有 Nginx 的 8000 端口暴露给 Windows。两只 Agent、PostgreSQL 和 Qdrant 只在 Docker 私有网络通信；
宿主机既不能直连 5432，也不能绕过 Agent 直连 6333。PostgreSQL 保存业务事实和工作流，Qdrant 只保存知识向量与切片 Payload。

两只Agent不再同时负责首次建索引。``index-knowledge`` 像开门前整理资料柜的一名工作人员：它先完成Collection
创建、切片写入和可读性检查，两只Agent确认该任务成功后才启动。这样既保留幂等补齐，也消除了多个副本同时抢建共享索引的启动竞争。

为什么需要两个 Agent
====================================================================================================

双实例演示两件事：入口可以负载分发；状态不只存在某个 Python 进程里。
例如 agent-a 创建的暂停流程，可以由 agent-b 从共享 PostgreSQL 读取并恢复；两只实例查询 FAQ 时也使用同一份 Qdrant Collection。

容器安全设置
====================================================================================================

* Agent 使用非 root 用户；
* 根文件系统只读；
* 删除 Linux capabilities，并禁止重新获得权限；
* 临时文件只写受限 tmpfs；
* 设置 CPU、内存和进程数边界；
* 使用健康检查和优雅停止时间；
* 镜像版本和摘要固定，减少无提示漂移。

GitHub Actions 做什么
====================================================================================================

每次推送或 Pull Request 会在全新 Linux 环境中：

1. 安装锁定版本的 Python 与依赖；
2. 运行 Ruff、Mypy 和 Pytest；
3. 运行离线 Agent 质量门；
4. 保留评测报告用于排错；
5. 其他工作流还可构建容器并执行 PostgreSQL 集成检查。

CI 证明“这个提交在干净环境中可以通过自动检查”，不等于已经部署到生产，也不等于无需人工评审。

发布安全
====================================================================================================

项目发布审计会检查 Git 候选文件中的高置信密钥模式、忽略规则、README 链接、冻结实验摘要、License 和首次提交。
``.env``、运行报告、备份、虚拟环境、IDE 配置和个人简历被排除。
