====================================================================================================
6. LangGraph：把流程画成可检查的地图
====================================================================================================

为什么使用 LangGraph
====================================================================================================

售后请求并不是固定的一条直线：FAQ 要检索，订单要调用工具，退货要暂停审批，异常还要转人工。
LangGraph 允许把每一步写成节点，把去向写成边，把共享数据写进 State。

与大量 ``if/else`` 相比，它的优势不是代码更短，而是合法路线、循环、暂停点和终点都能显式检查。

State 是什么
====================================================================================================

``ServiceState`` 是一张会随着流程移动的办事单。字段可以分成几组：

.. list-table::
   :header-rows: 1
   :widths: 25 35 40

   * - 组别
     - 例子
     - 用途
   * - 请求与身份
     - message、request_id、user_id
     - 知道用户问了什么，以及可信身份是谁
   * - 分类
     - intent、intent_confidence
     - 决定走 FAQ、订单、退货还是人工
   * - RAG
     - retrieval_hits、citations、has_sufficient_evidence
     - 保存找到的证据和放行决定
   * - 工具循环
     - planned_tool_call、tool_execution_records、agent_step_count
     - 记录准备调用什么、调用过什么、是否超步数
   * - 审批
     - return_request_proposal、approval_decision、return_workflow_status
     - 支持退货暂停与恢复
   * - 输出与事件
     - answer、events、requires_human
     - 形成最终回复和公开执行轨迹

节点、边和条件边
====================================================================================================

* **节点**：做一件明确的事，例如分类、检索或执行订单工具。
* **普通边**：上一步结束后固定去下一步。
* **条件边**：读取 State 后选择有限路线。
* **回边**：工具执行后回到规划节点，形成受控循环。
* **END**：这次图执行正式结束。

为什么路由函数默认转人工
====================================================================================================

路由函数不会因为某个字段“看起来像真值”就放行。例如 FAQ 必须同时存在明确的充分证据标志、非空答案和合法引用。
任何缺字段、矛盾状态或未知动作都会去人工路径。这叫 fail closed：不确定时先关门。

订单循环和 ReAct 的关系
====================================================================================================

订单路径使用了“行动—观察—再决定”的思想，但项目不依赖或展示隐藏思维链。工程上只保存：

* 结构化下一动作；
* 结构化工具参数；
* 工具执行记录；
* 明确的停止原因。

因此面试时可以说“受约束的工具调用循环”，不要声称系统保存了完整模型思维过程。

Checkpoint 是什么
====================================================================================================

Checkpoint 是节点边界的流程快照，不是业务事实本身。它适合保存“走到哪、下一步去哪、当前 State 是什么”。
订单真实状态和退货记录仍由业务仓储管理。

可以类比：Checkpoint 是快递运输轨迹，业务数据库是包裹本身的登记信息。运输轨迹不能替代真实库存或订单表。
