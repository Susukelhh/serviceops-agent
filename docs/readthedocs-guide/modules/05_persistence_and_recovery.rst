====================================================================================================
9. 持久化：程序重启后还能接着办
====================================================================================================

为什么不能只放内存
====================================================================================================

如果所有状态只放 Python 内存，进程重启后等待审批的退货流程就消失；两个 Agent 实例也看不到彼此的数据。
因此项目把不同类型的数据放进不同“档案柜”。

四类数据不要混在一起
====================================================================================================

.. list-table::
   :header-rows: 1
   :widths: 22 35 43

   * - 数据
     - 保存什么
     - 为什么独立
   * - Checkpoint
     - State、下一节点、暂停位置
     - 用于工作流恢复，不等同业务事实
   * - 业务记录
     - 退货申请及当前状态
     - 需要事务、唯一约束和业务查询
   * - Outbox
     - 等待投递的业务事件
     - 解决“业务成功但消息没发出”的一致性问题
   * - 审计链
     - 谁在何时批准或拒绝、前后哈希
     - 支持检查记录是否被插入、删除或篡改

三种持久化后端
====================================================================================================

* **memory**：启动快，适合单元测试，进程结束就丢失。
* **SQLite**：像单机文件账本，适合学习和单实例恢复。
* **PostgreSQL**：像多人共享档案室，适合双实例共同读写。

代码依赖的是 Repository 协议，业务节点不需要知道背后是哪一种数据库实现。

Transactional Outbox
====================================================================================================

创建退货后通常还要通知别的系统。如果先写业务表再发消息，进程可能刚写完就崩溃，导致业务成功但消息丢失。

项目把“退货记录”和“待发送事件”放在同一个数据库事务里：要么一起成功，要么一起失败。随后对账器读取 Outbox 并投递；失败可以重试。
这不能代替 Kafka 等消息系统，但解决了本项目内部的落库一致性问题。

审计哈希链
====================================================================================================

每条审批记录保存上一条哈希和当前内容哈希。验证时重新计算整条链，可以发现中间记录被修改、删除或插入。
它提供篡改迹象，不等于电子签名、可信时间戳或不可抵赖法律证据。

Alembic 迁移
====================================================================================================

数据库表结构会随着代码升级。Alembic 像数据库的版本升级脚本。Compose 先运行一次 ``migrate``，成功后两只 Agent 才启动，
避免新代码连接旧表结构。

备份恢复演练
====================================================================================================

项目通过 ``pg_dump`` 生成带 SHA-256 清单的备份，再恢复到程序生成的临时数据库，比较表集合、行数和内容指纹，最后删除临时库。
代码明确拒绝把演练恢复到真实 ``serviceops`` 数据库。

这证明“备份真的能恢复”，但不等于生产高可用、异地副本或按时间点恢复；生产仍需云数据库备份和 WAL 方案。
