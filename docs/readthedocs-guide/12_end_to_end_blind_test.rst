====================================================================================================
19. 新版端到端盲测：先失败，再用证据修复
====================================================================================================

为什么还需要一套新版盲测
====================================================================================================

第13步和第14步主要从 Python 内部构造 LangGraph 目标，适合快速、稳定地检查节点和模型候选。
第33步换了一个角度：评测器只知道 Nginx 地址，所有行为都必须经过公开 HTTP 接口。

因此它同时覆盖：

* Nginx 是否能把请求分给两只 FastAPI；
* 五项 readiness 依赖是否可读；
* 公网短时身份是否真实可用且相互隔离；
* 新口语措辞能否正确进入订单、FAQ、安全和退货四条路径；
* 订单工具、Qdrant 引用和零工具安全出口是否符合契约；
* 退货是否真的创建 interrupt 和 Checkpoint，而不只是回答里写“等待审批”；
* 批准后是否恢复同一线程、执行写工具并形成有效审计链；
* 另一名访客是否始终只能得到不泄漏存在性的 404；
* 匿名超长输入是否在进入图前被拒绝。

为什么叫“盲测”
====================================================================================================

``public_demo_end_to_end_blind_test.json`` 中的四条问题使用了此前没有参与关键词、提示、检索阈值
和前端场景调优的新措辞。第一次冻结运行前不根据程序输出修改标签，运行后也不通过删题或降低阈值
换取 PASS。

这不是永远保密的数据集。第一次揭晓后，它就从一次性盲测转为新的回归集。下次需要检验未知分布时，
应建立新的版本和新 holdout，不能反复把 v1.0.0 称作盲测。

第一次为什么失败
====================================================================================================

首次运行只有 ``6/11`` 通过：整体 ``54.55%``、业务 ``33.33%``、恢复 ``0%``，但可用性和安全
隔离都是 ``100%``。这说明 Docker、数据库、Qdrant 和身份边界没有坏，问题集中在自然语言入口。

两个根因是：

1. ``送到哪一步`` 没有命中旧订单关键词，系统安全地转了人工，但失去了本可自动完成的工具调用；
2. ``已经收到，但尺寸不合适`` 已识别为退货，却因为没有写 ``原因：`` 而无法生成完整草案。

退货没有创建草案，后面的 interrupt、恢复和审计自然全部连锁失败。不能把它误诊成四个独立故障。

如何修复
====================================================================================================

订单分类补充 ``送到哪``、``配送进度`` 和 ``运输进度`` 三类同义表达。退货参数没有改成“让模型猜”，
而是增加受限制的确定性因果语法：只有 ``原因/理由`` 标签，或 ``因为/由于/但/不过`` 等明确连接词
才提取原因，并且只截取到下一个标点，长度仍由 Pydantic 校验。没有明确原因的请求继续追问。

修复后 P95 黑盒耗时约 ``426.10 ms``，只代表本次本机 Docker 环境，不应写成生产 SLA。

如何运行
====================================================================================================

先确认 Docker Compose 全部健康，然后在 PyCharm 运行：

.. code-block:: powershell

   D:\Python\Scripts\uv.exe run D:/serviceops-agent/.venv/Scripts/python.exe D:\serviceops-agent\examples\33_public_demo_end_to_end_blind_test.py

退出码 ``0`` 表示完整质量门通过，退出码 ``1`` 表示至少一项硬检查或聚合门失败。完整本机报告位于
``data/runtime/public_demo_blind_report.json``；版本化的修复前后证据位于 ``data/evaluation/results``。

面试怎么说
====================================================================================================

可以按“现象—定位—改动—效果—边界”回答：

   我没有把已有开发集的100%继续当结论，而是从Nginx入口增加11项黑盒盲测。首次只有6项通过，
   我按维度发现基础设施和安全都是100%，失败集中在口语订单分类和退货原因抽取，并识别出后三项是
   退货未暂停造成的连锁失败。我保留原题和质量门，只扩展订单同义表达，并加入有限因果语法抽取，
   复测从6/11提升到11/11。这个结果只证明当前冻结集和本机部署，不代表未知线上表达永远100%。
