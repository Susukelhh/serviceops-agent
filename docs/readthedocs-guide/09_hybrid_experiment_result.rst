16. RRF混合召回实验：为什么没有直接晋级（项目第31步）
====================================================================================================

一句话结论
====================================================================================================

独立Qdrant、全库BM25和RRF已经实现；74条开发题的Top-1从纯向量83.87%提升到93.55%。但是冻结参数在
16条新锁定题上误放行2/4条域外问题，FPR为50%，所以开发优胜配置没有晋级生产。

这不是“项目做失败了”，而是质量门正常发挥作用：它阻止我们把局部排序提升误写成整个系统可以安全上线。

为什么不能写“召回率提高”
====================================================================================================

当前只有12份公开知识文档、23个切片，纯向量Top-5已经找回全部正确父文档。Dense与Lexical并集Recall仍为
100%，关键词独有救回数为0。因此这次RRF收益是把正确资料排得更靠前，不是救回原本找不到的资料。

锁定集暴露了什么
====================================================================================================

12条知识内题全部召回，Top-1为91.67%；但“有雨吗”和“写一篇考试作文”没有命中确定性范围规则，进入检索后
都找到了表面相似售后资料。4条域外题错2条，FPR为50%，最终Gate FAIL。

这说明系统至少有两道不同关卡：

.. code-block:: text

   用户问题
      ↓
   意图/范围判断：这件事该不该查售后资料？
      ↓
   RRF检索排序：允许查询后，哪些资料最相关？

RRF只能优化第二关，不能替代第一关。下一步应把已揭晓Bad Case转成意图分类开发回归题，并使用新的未知
holdout验证“规则优先 + 模型兜底”是否值得引入。

面试回答抓手
====================================================================================================

不要回答“最大难点是接Qdrant”。更好的说法是：最大难点是避免局部检索指标掩盖完整决策风险。你通过四路
对照证明排序改善，再通过新锁定集发现范围漂移，最终主动拒绝晋级；这体现的是问题拆分、实验纪律和上线判断。
