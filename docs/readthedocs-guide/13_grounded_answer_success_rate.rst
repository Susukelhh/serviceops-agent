====================================================================================================
13. 端到端有据回答成功率：最终答案必须真的答对
====================================================================================================

第29步还缺了什么
====================================================================================================

第29步已经能检查正确文档是否进入候选、模型是否回答、引用编号是否来自本轮候选，以及是否引用了
人工标注的正确父文档。但它没有检查 ``answer`` 中的关键事实。

例如，系统找到了七天退货规则并给出合法引用，却把期限写成十五天。旧口径可能通过，因为
“引用了正确文档”不等于“答案中的每个结论都由引用切片支持”。第34步专门补上这个缺口。

唯一主指标
====================================================================================================

只有一个放在最前面的质量数字：

.. code-block:: text

   端到端有据回答成功率 = 严格完整通过的题数 / 全部密封盲测题数

每题只能是 ``1`` 或 ``0``，没有部分分。

可回答题需要同时通过范围、检索、回答、引用白名单、必要来源、全部关键事实、实际引用证据支持和
禁止结论检查。知识缺口题必须拒绝自动回答并且不返回引用。任何一层失败，整题就是0分。

逐题错误码仍会保留，用来判断该修范围门、召回、生成还是引用；它们不是另一串用来包装结果的主指标。

.. important:: 零容忍红线

   明确错误结论、非法或不支持答案事实的引用，以及知识缺口上的自动回答会直接否决质量门。
   红线不是第二个平均分，而是防止大量简单题把一条严重错答平均掉。

事实和证据怎样一起检查
====================================================================================================

私有金标把一条答案拆成少量原子事实。每个事实分别声明答案中的可接受表述、引用证据中的原文锚点，
以及可以支持它的父文档。只有答案表达和实际引用切片同时命中，事实才算正确。

禁止结论使用完整错误说法，不用一个含义模糊的单词判错。评分前还会统一全角半角、大小写、空白和
标点；``7天`` 与 ``七天`` 等字符不同的等价说法由金标显式列为替代表述。事实标签只在模型返回后
评分，绝不会进入问题、检索查询或生成提示词。

揭晓前还会使用冻结的切片参数真正切分语料，逐条验证证据锚点能在允许来源的实际切片中命中，避免
人工标签错误把候选误判为失败。

密封盲测为什么可信
====================================================================================================

公开配置只保存题量、题集SHA、语料SHA、候选指纹和事先冻结的门槛。题目正文与事实金标放在
``data/private_evaluation``，该目录不进入Git，也不进入Docker构建上下文。

当前契约是25道新题：19道可回答题和6道知识缺口题。候选参数在读取私有题目前已经形成SHA-256指纹，
加载器还会检查题目没有复制此前已经揭晓的数据集。

同一版本只有第一次冻结候选运行可以叫盲测。结果揭晓后：

* 不能删掉失败题或降低门槛；
* 失败题可以转成开发回归题；
* 修复后复跑必须标记 ``REGRESSION``；
* 下一次未知验证必须建立新的v2密封集。

当前结果
====================================================================================================

零费用 ``Hash + BM25 + RRF + Extractive`` 对照已经首次运行：严格通过 ``14/25``，端到端有据回答
成功率为 **56%**，质量门 ``FAIL``。5道可回答题遗漏了必要事实，6道知识缺口题全部被相似资料带偏并
自动回答，触发零容忍红线。

首次千问冻结候选严格通过 ``10/25``，端到端有据回答成功率为 **40%**，质量门 ``FAIL``。它把知识
缺口正确拒答从Extractive的 ``0/6`` 提升到 ``5/6``，但19道可回答题只有5道完整覆盖全部必要事实。
没有禁止事实或非法引用；唯一红线是一道知识缺口仍被自动回答。

.. warning:: 首次FAIL必须保留

   这不表示Extractive整体更可靠：它靠复制整段证据更容易碰齐关键词，却对全部知识缺口强行回答。
   千问更会拒答，但经常省略必要条件。首次结果已经冻结，v1只能作为回归集，不能反复调到100%后
   继续称为盲测。

揭晓后的人工审计显示，14道“必要事实缺失”中约8道确实漏了用户直接询问的核心结论，约6道的缺失项
更像背景、重复结论或可选流程说明。首次运行没有保存原始答案，所以不能正式重算。40%继续作为v1严格
口径的首次结果；后续应使用本机私有诊断把模型漏答、匹配器漏判和金标过严分开，再用新的v2密封集验证。

PyCharm三种运行方式
====================================================================================================

三个配置共同填写：

* Script path：``D:\serviceops-agent\examples\34_grounded_answer_success_experiment.py``
* Working directory：``D:\serviceops-agent``
* Interpreter：``D:\serviceops-agent\.venv\Scripts\python.exe``

只改变 Parameters：

.. list-table::
   :header-rows: 1
   :widths: 24 33 43

   * - 模式
     - Parameters
     - 行为
   * - 安全预检
     - 留空
     - 只展示题量、SHA、候选指纹和费用计划，不读取私有题目
   * - 零费用对照
     - ``--confirm-blind``
     - 读取密封集，运行Hash、BM25、RRF和Extractive，不调用千问
   * - 首次真实候选
     - ``--confirm-blind --confirm-paid-api``
     - 调用冻结的真实千问候选，产生费用并保存首次脱敏证据

首次结果已经存在后，同一题集只能使用
``--confirm-blind --confirm-paid-api --regression`` 复跑。它是回归，不是新的盲测，也不会覆盖首次证据。

如何用于面试
====================================================================================================

可以这样解释设计动机：

   我发现检索命中和引用合法并不能保证答案事实正确，因此没有继续堆更多检索指标，而是建立一个
   全或无的端到端成功率。可回答题必须把全部关键事实答对，并由实际引用切片逐事实支撑；知识缺口题
   必须拒答。题集、候选和门槛先冻结，同一题揭晓后只作为回归，避免把反复调参后的100%包装成盲测结果。

完整实施记录见 ``docs/steps/34-end-to-end-grounded-answer-success-rate.md``。
