====================================================================================================
21. 怎么把项目讲清楚
====================================================================================================

一分钟介绍模板
====================================================================================================

“我做的是一个企业售后场景的生产导向 AI Agent 个人项目，支持 FAQ、订单查询和退货申请三类任务。
我没有让模型直接操作业务，而是用 LangGraph 显式编排路线：FAQ 必须经过 RAG 证据与引用校验，订单使用受约束工具循环，
退货通过 Checkpoint 暂停并由人工审批后再幂等写入。项目还实现 PostgreSQL 共享状态、Outbox、审计链、OpenTelemetry、
Docker 双实例和自动评测。我的重点不是堆框架，而是针对误召回、候选排序和无依据回答分别做实验，并用开发集和锁定集验证。
这是个人项目，没有真实线上流量，所有指标都限定在公开的小型评测集内。”

三分钟讲解结构
====================================================================================================

1. **背景，20 秒**：售后同时有知识问答、只读查询和高风险写操作。
2. **架构，40 秒**：接入安全、LangGraph、RAG/工具、持久化、评测部署五层。
3. **难点一，40 秒**：阈值无法兼顾 Recall/FPR，因此引入范围门。
4. **难点二，40 秒**：旧 BM25 救不回向量榜外文档，因此升级为两路全库召回 + RRF，并保留通道级解释和历史基线。
5. **难点三，30 秒**：相关不等于可回答，因此加入证据充分性与引用白名单。
6. **工程安全，30 秒**：人工审批、幂等、Outbox、审计、共享 Checkpoint。
7. **边界，20 秒**：个人项目、小型锁定集、无线上 SLA，下一步扩大真实语料与部署验证。

STAR 不要背字面
====================================================================================================

每个故事只记四个关键词：

* **S**：出现了什么具体失败；
* **T**：你要改善哪个指标，同时守住什么边界；
* **A**：比较了哪些候选，为什么选择当前方案；
* **R**：开发集与锁定集分别怎样，仍有什么失败。

范围门故事示例
====================================================================================================

* S：低阈值让 8 条域外问题全部误召回。
* T：降低 FPR，同时不能把正常售后问题一起拒绝。
* A：扫描 6 档阈值，发现 0.30 虽使 FPR 为 0，但 Recall@5 只剩 20.8%；因此把“业务范围判断”放到 Embedding 前。
* R：开发集 FPR 从 100% 降到 0，Recall 保持 100%；冻结候选通过 12 条锁定集，但 Top-1 仍只有 75%，所以下一步单独做排序实验。

意图漂移故事示例
====================================================================================================

* S：13条整图回归全过，但32条专项题揭示关键词分类Accuracy只有62.5%，危险自动放行率40%。
* T：提高四分类Macro-F1和人工接管召回，同时守住“普通咨询不能进入退货写操作”的边界。
* A：千问v1仍会以0.95置信度误判，证明只调阈值没用；因此从Bad Case提炼安全边界，改写结构化提示，并冻结提示指纹和0.85阈值。
* R：v2通过32条开发题和一次性16条锁定题，危险自动放行率与错误退货路由均为0；但样本规模仍小，不能外推为线上100%。

被问到不会的内容
====================================================================================================

可以使用三句话：

1. “这个能力当前项目没有实现，我先说明边界。”
2. “我理解它主要解决的是……，如果放进本项目，我会接在……这一层。”
3. “我会先用……指标做候选实验，而不是直接替换默认链路。”

证据定位习惯
====================================================================================================

任何简历数字都准备三类证据：

* 运行脚本：如何复现；
* 数据集：样本从哪里来、开发和锁定如何隔离；
* 报告：成功、失败、指纹和边界在哪里记录。

面试前自测
====================================================================================================

关闭本文档，独立回答：

1. 为什么三条业务路线不能共用一种处理方法？
2. 为什么“召回相关文档”仍可能产生无依据回答？
3. 审批前零写入由哪几层共同保证？
4. 100% 指标为什么不能写成线上准确率？
5. 如果下周加入 MCP，你会要求先出现什么业务问题？

如果其中一题说不清，回到对应模块而不是继续背新名词。
