====================================================================================================
18. HR 会怎么问这个项目
====================================================================================================

HR 通常不会深挖 BM25 公式，但会判断：动机是否真实、项目是不是你能讲清楚、毕业与到岗是否稳定、表达有没有夸大。

1. 请用一分钟介绍你自己
====================================================================================================

**考察：** 目标是否明确，能否把教育背景、核心项目和岗位匹配串起来。

**回答主线：** 真实教育背景 → 近期聚焦 AI Agent 应用 → 独立完成 ServiceOps Agent → 最熟悉 LangGraph、RAG、工具安全和评测 → 希望在杭州从事大模型应用开发。

2. 为什么想做 AI Agent，而不是普通后端
====================================================================================================

**考察：** 是追热点还是有持续兴趣。

不要只说“AI 很火”。可以说你喜欢把不稳定的模型能力变成可控制、可评测的业务流程；项目中最吸引你的不是聊天效果，而是状态、工具、审批和证据链如何组合。

3. 这个项目是课程作业、开源二开还是你自己的项目
====================================================================================================

**考察：** 贡献真实性。

如实说明它是 AI 辅助完成的个人项目，参考了官方文档和面试资料，但架构、实验、代码与验证都在自己的仓库中逐步落地。
你需要能演示代码、解释取舍，并指出哪些部分目前还不能独立修改。

4. 你在项目里具体负责什么
====================================================================================================

这是个人项目，不要使用“我们团队上线”。可以回答自己覆盖了需求拆分、编排、RAG 实验、后端、数据库、测试、Docker 和文档，
同时强调主线深度在“可控 Agent + 问题驱动评测”，不是所有技术都达到生产专家水平。

5. 项目解决了什么业务问题
====================================================================================================

不要从 LangGraph 开始说。先说售后场景中 FAQ 依据不清、订单工具可能越权、退货写操作需要审批、失败难追踪，再说系统如何逐个控制这些风险。

6. 为什么选择售后场景
====================================================================================================

售后同时包含知识问答、只读查询和高风险写操作，能在一个小而完整的领域里展示 Agent 的三种典型路线；公开种子数据也便于本地复现，不需要冒充真实公司数据。

7. 项目最大的挑战是什么
====================================================================================================

推荐讲端到端 RAG：语义 Embedding 能找到更相似资料，却把“数字人民币支付”误匹配到“数字商品规则”。
你没有靠继续调阈值掩盖，而是把问题拆成检索和证据充分性两层，最后用新锁定集验收组合链路。

8. 项目中最能体现你解决问题能力的地方
====================================================================================================

可以讲阈值实验：FPR 降到 0 时 Recall 只剩 20.8%，证明单纯升阈值不可行；随后引入业务范围门，开发集 FPR 降到 0 且 Recall 保持。
重点是“先用数据证明旧方案为什么失败，再引入更合适的层”。

9. 项目有没有真实用户或线上数据
====================================================================================================

必须诚实回答没有。它是本地和容器环境中的生产导向个人项目，结果来自小型开发集、一次性锁定集、真实千问 API 实验和自动测试，不能外推到线上流量。

10. GitHub 上我能看到什么
====================================================================================================

代码、架构、逐步实验、脱敏冻结结果、自动化工作流和 MIT License。不会看到 ``.env``、API Key、个人简历、运行数据库和备份。

11. 你的项目用了很多技术，会不会只是拼装
====================================================================================================

回答时只选三条因果链：LangGraph 解决多路线与暂停恢复；范围门 + BM25 + Grounded 判断分别解决误召回、排序和无依据回答；
PostgreSQL + Outbox + 审计链解决跨实例恢复、可靠写入和追责。每条都给代码或实验证据。

12. 你是 26 届，毕业时间为什么变化
====================================================================================================

按真实情况简短说明原因、当前学业状态、预计毕业日期和不会影响工作的安排。不要回避，也不要展开成长期辩解。
重点是信息一致：简历、学信网、到岗日期和口头回答不能冲突。

13. 什么时候可以到岗，能实习多久
====================================================================================================

只给真实日期、每周天数、毕业前后安排。HR 更看重确定性，不要为拿面试承诺无法做到的全勤。

14. 为什么选择杭州和我们公司
====================================================================================================

杭州原因可以结合长期生活意愿和 AI 应用岗位密度；公司原因必须在投递前查看产品、业务场景和 JD，说明项目里的哪项能力能迁移过来。

15. 如果没有拿到 Agent 岗，你会怎么办
====================================================================================================

可以表达主目标仍是大模型应用/Agent，同时接受与目标高度相关的 Python 后端、RAG 应用或模型平台岗位，继续积累工程和业务经验。
这比“只接受一个岗位名”更稳健。
