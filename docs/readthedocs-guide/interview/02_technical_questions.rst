====================================================================================================
19. 技术面高频问题
====================================================================================================

下面的问题来自面试指南中的架构、RAG、工具、工程化和故障处理主题，并按本项目真实实现重新组织。

架构与 LangGraph
====================================================================================================

1. **为什么选择 LangGraph，不用一条 LangChain Chain？**

   回答：项目有条件分支、工具回环、人工暂停和跨请求恢复；线性 Chain 难以显式表达这些状态转换。LangGraph 让节点、路线、停止条件和 Checkpoint 可测试。

2. **ServiceState 里为什么有这么多字段，会不会失控？**

   回答：按请求、分类、RAG、工具、审批、输出分组；节点只返回局部更新。风险是 State 逐渐膨胀，所以用强类型字段、领域模型和调试白名单控制。

3. **订单路径属于 ReAct 还是 Plan-and-Execute？**

   回答：它是受约束的“行动—观察—再规划”循环，更接近 ReAct；没有一次生成完整长计划，也不保存隐藏思维链。简单订单最多需要少量工具步数，ReAct 式反馈更合适。

4. **如何防止 Agent 死循环？**

   回答：最大工具步数、工具调用指纹去重、有限动作枚举、执行失败转人工、只有明确 ``continue`` 才允许回边。

5. **为什么不做多 Agent？**

   回答：当前三条路线共享一个用户请求和状态，单图多节点已经能清楚隔离职责。拆多 Agent 会增加通信、状态同步和评测难度，却没有独立目标带来的收益。

6. **Checkpoint 和数据库业务表有什么区别？**

   回答：Checkpoint 保存流程位置和 State，用来恢复；业务表保存真实退货事实。两者生命周期、查询和一致性要求不同，不能互相替代。

模型与工具
====================================================================================================

7. **模型是怎么选择工具的？**

   回答：规划器返回有限动作和 Pydantic 工具调用结构；执行节点再校验白名单、参数、身份、重复和步数，最后才运行 Tool。

8. **如何防止模型查到别人的订单？**

   回答：user_id 来自已验证 JWT，不来自自然语言或模型参数；工具闭包和仓储查询绑定可信 user_id 与 order_id。

9. **模型输出 JSON 失败怎么办？**

   回答：结构化输出需要通过 Pydantic；解析失败被分类为模型输出错误，按策略重试或转人工，不把原始文本直接执行。

10. **高风险工具为什么需要人工审批？**

    回答：退货会改变业务事实。系统先生成草案并 interrupt，批准前零业务写入，reviewer 用独立权限恢复流程，后端仍重复校验。

11. **为什么没用 MCP？Function Calling 和 MCP 有什么区别？**

    回答：Function Calling 描述模型如何提出调用；MCP 统一应用与外部工具/资源的连接。当前工具少且同进程，直接注册更简单。MCP 不能替代权限、幂等和审批。

RAG
====================================================================================================

12. **Chunk 怎么切，为什么是 500/80？**

    回答：当前按字符固定窗口 500，重叠 80，用于小型政策语料基线和跨边界句子保留。它不是通用最优参数；语料扩大后要做标题感知、语义切片和父子文档对照。

13. **Embedding 用什么模型，为什么默认不是千问？**

    回答：离线默认 Hash 1024 维，用于零费用可重复测试；真实候选用 qwen3.7-text-embedding 1024 维。语义候选正例提升，但单独锁定安全门失败，因此默认不能悄悄替换。

14. **为什么选择 Qdrant？**

    回答：客户端既支持单测内存模式，也支持独立服务；Compose中两只Agent共用持久化Collection，一次性 ``index-knowledge`` 任务先串行建库，``/ready`` 再真实探测它。没有做Milvus/pgvector基准，因此不声称它对所有规模都最优。

15. **BM25 是混合检索吗？**

    回答：旧版只是候选内重排；新版 BM25 与 Qdrant 都独立检索全部切片，再用 RRF 合并，因此属于完整双路召回。旧模式仍可配置，用来复现历史实验。

16. **为什么用 RRF，不直接把余弦分数和 BM25 分数相加？参数怎么解释？**

    回答：两种分数的量纲和分布不同，直接相加需要额外校准；RRF 只使用各自名次，更稳、更容易解释。当前 ``k=60``、向量权重 1.0、词面权重 0.8 是工程初始值，尚未冒充实验最优值；要先在开发集选择，再冻结后跑锁定集。

17. **RAG 效果不好怎么定位？**

    回答：先分层：正确文档不在候选是召回问题；在候选但靠后是排序问题；文档相关但不含答案是证据判断问题；有证据却回答错是生成问题。不同层不能用一个阈值解决。

18. **如何控制幻觉？**

    回答：知识发布过滤、业务范围门、相似度阈值、候选重排、结构化 ``is_answerable``、引用白名单、答案后路由校验和人工兜底；并用知识缺口负例测无依据回答率。

19. **RAG 和微调怎么选？**

    回答：变化快且需要引用的政策事实用 RAG；稳定行为、风格或格式可考虑微调。两者可组合，本项目未做微调。

数据、安全与可靠性
====================================================================================================

20. **为什么从 SQLite 升级 PostgreSQL？**

    回答：SQLite 适合单机学习；双 Agent 需要共享 Checkpoint 和业务状态，PostgreSQL 提供并发事务、连接池和成熟备份工具。

21. **Transactional Outbox 解决什么？**

    回答：业务记录和待发送事件同事务落库，避免业务成功但通知因进程崩溃丢失；对账器之后重试投递。

22. **审计哈希链能防止数据库管理员改数据吗？**

    回答：能检测链内容不一致，但如果攻击者同时重算整条链且控制所有副本，单库哈希链无法阻止。生产需外部不可变存储、签名或可信时间源增强。

23. **并发能力是多少？**

    回答：当前配置每实例最多 8 个高成本在途请求，双实例约 16 个工位；这是容量保护配置，不是线上 QPS。真实容量需说明硬件、请求类型和压测结果。

24. **模型超时、429、5xx 怎么办？**

    回答：设置超时，区分可重试暂时错误与鉴权等不可重试错误，限制重试次数并安全降级；同时用容量保护避免内部排队放大。

评测与交付
====================================================================================================

25. **为什么很多结果是 100%，是否测试太简单？**

    回答：100% 只对应 10～13 条专项锁定题或黄金集；文档明确不外推。开发集仍保留失败样本，且语义 Embedding 锁定门曾 FAIL，证明流程不是只保留成功结果。

26. **如何证明优化来自 BM25，而不是换了候选？**

    回答：旧候选内重排实验要求候选集合违规数为 0，只比较 Top-1 和 MRR；新版混合召回的目标本来就允许 BM25 救回向量榜外文档，所以应另外报告 dense Recall、lexical Recall、union Recall、融合 Top-1/MRR、负例误召回率和端到端无依据回答率，不能沿用旧归因口径。

27. **开发集和锁定集如何防止数据泄漏？**

    回答：开发集用于调参，候选配置和指纹冻结后才允许显式 ``--confirm-holdout`` 运行一次；失败锁定题之后进入下一版开发回归，不继续冒充未知题。

28. **如何测试 Agent，而不仅是 LLM 输出？**

    回答：验证路由、工具轨迹、响应契约和安全不变量；再分单元、集成、API、数据库和容器层测试。

29. **Docker Compose 为什么有 migrate 服务？**

    回答：先确保数据库表结构升级成功，再启动 Agent，避免新代码接旧 Schema；迁移成功退出是正常行为。

30. **如果要真正上线，最先补什么？**

    回答：独立 Qdrant 已有，但还需离线建索引、别名切换和回滚；同时补真实身份与 Secret 管理、更大盲测、HTTPS、告警和托管备份，之后再谈 K8s 或多 Agent。

31. **意图分类为什么不能只看整图13/13？你是怎样优化的？**

    回答：13条整图黄金集主要查流程回归，覆盖不了同义改写和业务词碰撞。我另建32条四分类困难开发题，发现关键词基线Accuracy只有62.5%，危险自动放行率40%。千问v1虽把Accuracy提高到87.5%，但4个错误都以0.95高置信度发生，所以继续调阈值无效。我把内部政策、域外请求、越权和高风险判断明确归入人工接管，并把“咨询退货”和“执行退货”分开；v2在32条开发题和一次性16条锁定题上均通过，随后才把提示和0.85阈值晋级生产。这里的100%只属于48条版本化样本，不代表线上准确率。
