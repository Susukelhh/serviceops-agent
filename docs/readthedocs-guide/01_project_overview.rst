====================================================================================================
1. 项目到底做了什么
====================================================================================================

一句话版本
====================================================================================================

ServiceOps Agent 是一个“企业售后接待员”：它接收用户问题，先判断属于 FAQ、订单查询还是退货申请，
再走不同的处理路线；遇到知识不足、身份不可信、工具失败或高风险写操作时，不擅自猜测，而是拒答、追问或暂停等待人工审批。

它解决的不是“让模型更会聊天”，而是下面四个工程问题：

* **回答有没有依据**：FAQ 必须找到已发布的企业知识，并附上合法引用。
* **工具能不能乱用**：订单工具只能查询当前登录用户自己的订单。
* **写操作谁来负责**：退货申请必须先暂停，收到审批人的明确决定后才能写数据库。
* **失败后能不能查清楚**：请求过程、工具结果、审批决定、Checkpoint 和审计记录都能回看。

生活类比
====================================================================================================

把系统想象成一家售后服务大厅：

* FastAPI 是前台窗口，负责接收材料并给出回执。
* JWT 是身份证和工作证，决定“你是谁、能办什么”。
* LangGraph 是办事流程图，规定先去哪个柜台、什么条件才能去下一个柜台。
* State 是随请求流转的办事单，记录当前已经知道什么。
* RAG 是企业政策资料室，只能从正式发布的文件中找答案。
* Tool 是业务系统窗口，真正查询订单或创建退货记录。
* Checkpoint 是流程快照；办到一半停下，之后还能接着办。
* PostgreSQL 是多人共享的档案室。
* OpenTelemetry 是路上的监控编号，帮助定位哪一段慢或失败。
* Docker 是统一规格的搬家箱，把代码和运行环境一起带走。

为什么它算 Agent
====================================================================================================

普通聊天接口通常是“问题进去，答案出来”。这个项目多了一层可控决策：

1. 它会根据意图选择不同路线。
2. 订单路线允许模型在受限制的动作集合中决定“调用工具、结束、追问还是转人工”。
3. 工具结果会重新写回状态，再由规划节点决定下一步。
4. 退货路线可以跨一次人工审批暂停和恢复。
5. 每条路线都有停止条件和安全默认出口。

因此它不是“模型说什么就做什么”，而是“模型只在流程允许的范围内提建议，后端负责验证和执行”。

项目中的四类角色
====================================================================================================

.. list-table::
   :header-rows: 1
   :widths: 20 30 50

   * - 角色
     - 能做什么
     - 不能做什么
   * - customer
     - 提问、查询自己的订单、提交退货意图
     - 不能审批、查看审计链或开发调试信息
   * - reviewer
     - 批准或拒绝处于等待状态的退货流程
     - 不能冒充客户发起业务，也不能查看审计员信息
   * - auditor
     - 读取最小化的审批审计链
     - 不能替代审批人执行决定
   * - developer
     - 在开发/测试环境读取脱敏的 Checkpoint 时间线
     - 不能继承客户、审批、审计或运维权限

真实边界
====================================================================================================

这是一个生产导向的个人项目，不是已经在线承载真实企业流量的生产系统。

已经真实完成的部分包括：LangGraph 编排、受控 Tool Calling、RAG 实验、人工审批、共享 PostgreSQL、
事务性 Outbox、审计哈希链、OpenTelemetry、Docker Compose 双实例、备份恢复演练、自动测试与 GitHub Actions。

没有实现的部分包括：MCP、Redis 长期记忆、多智能体协作、Kubernetes、真实告警平台、线上灰度流量、模型微调和真实企业 SSO。
面试时主动说清边界，比把参考资料中的所有名词都算进项目更可信。
