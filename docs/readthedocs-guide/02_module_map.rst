====================================================================================================
2. 项目拆成哪几个模块
====================================================================================================

项目可以拆成九个模块。拆模块不是为了显得复杂，而是为了让每一类问题有明确负责人。

九个模块总览
====================================================================================================

.. list-table::
   :header-rows: 1
   :widths: 18 25 32 25

   * - 模块
     - 大白话职责
     - 主要技术
     - 核心代码
   * - 1. 接口与安全
     - 接住请求，确认来人身份，挡住越权请求
     - FastAPI、Pydantic、JWT、RBAC
     - ``api/``、``security/``
   * - 2. Agent 编排
     - 决定先做什么、下一步去哪、何时停止
     - LangGraph、TypedDict、条件边
     - ``graph/``、``agent/``
   * - 3. 三条业务路径
     - 分别处理 FAQ、订单和退货
     - 节点函数、领域模型、路由函数
     - ``graph/nodes/``、``domain/``
   * - 4. RAG
     - 从正式知识里找证据、排序、判断能否回答
     - Chunk、Embedding、Qdrant、BM25
     - ``rag/``
   * - 5. 工具与审批
     - 查询或写入真实业务数据，高风险动作先等人工
     - LangChain Tool、Pydantic、interrupt
     - ``tools/``、``graph/nodes/returns.py``
   * - 6. 持久化与恢复
     - 保存流程快照、业务记录、Outbox 和审计
     - SQLite、PostgreSQL、Alembic
     - ``infrastructure/``、``migrations/``
   * - 7. 稳定性与观测
     - 限制拥堵、记录链路、处理外部模型故障
     - 信号量、重试、OpenTelemetry
     - ``api/app.py``、``observability/``
   * - 8. 教学控制台
     - 把公开执行步骤、引用和快照展示给人看
     - HTML、CSS、JavaScript、脱敏接口
     - ``web/``、``api/debug_trace.py``
   * - 9. 评测与交付
     - 用固定题目验收版本，再打包和自动检查
     - Pytest、Ruff、Mypy、Docker、GitHub Actions
     - ``evaluation/``、``tests/``、``examples/``

模块之间怎么配合
====================================================================================================

.. code-block:: text

   浏览器 / Swagger
          │
          ▼
   [接口与安全]──验证身份、限制并发
          │
          ▼
   [LangGraph 编排]──读取 State，选择路线
       │       │       │
       ▼       ▼       ▼
     FAQ     订单查询   退货申请
      │         │         │
    [RAG]     [只读工具]  [人工审批 + 写工具]
       └─────────┬─────────┘
                 ▼
        [Checkpoint / 业务库 / 审计 / Outbox]
                 │
                 ▼
          [API 响应 + 控制台时间线]

为什么不把所有逻辑写在一个文件里
====================================================================================================

如果让一个大函数完成鉴权、模型调用、数据库写入和回复生成，会出现三个问题：

* 出错时不知道是哪一层的问题。
* 单元测试很难只验证某个规则。
* 更换数据库、模型或检索器时会牵动全部代码。

本项目通过“协议 + 实现”的方式拆分依赖。例如图节点只认识 ``OrderRepository`` 的接口，
并不关心数据来自内存、SQLite 还是 PostgreSQL。这样测试可以用内存版本，单机学习可用 SQLite，双实例演示再切 PostgreSQL。

面试时的模块表达
====================================================================================================

不要一口气背九个模块。先说五层即可：

1. 接入安全层；
2. LangGraph 编排层；
3. RAG 与工具执行层；
4. 持久化和可靠性层；
5. 评测、观测与部署层。

面试官追问哪层，再展开对应模块。
