优先级建议
====================================================================================================

如果目标是近期求职，不应继续无限加技术。建议顺序：

1. 能独立讲清现有代码和四个实验故事；
2. 用真实招聘 JD 做 2～3 轮模拟面试；
3. 部署一个可访问的只读演示环境或录制 3 分钟视频；
4. 独立 Qdrant + 完整混合召回已经补齐，下一步优先扩大盲测并形成真实对照指标；
5. 长期再考虑记忆、多智能体、Kubernetes 和微调。

为什么不是先加 MCP
====================================================================================================

MCP 热度高，但面试官更关心“为什么需要”。当前只有两个核心业务工具，直接 Tool Calling 足够。
如果为了简历加入一个计算器 MCP，没有解决新问题，反而容易被追问权限、连接管理、工具发现和故障隔离时露出薄弱点。

好的补充应该有可验证故事，例如：“工具来自三个独立服务，原先每个都写一套适配代码，因此引入 MCP 统一发现与调用；
同时保留后端 Scope 校验和审批门，接入时间和错误定位得到可测改善。”
