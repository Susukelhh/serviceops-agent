====================================================================================================
11. 公网 Demo：让面试官打开就能体验
====================================================================================================

它展示什么
====================================================================================================

公网 Demo 不是另一套简化代码，而是同一份 FastAPI、LangGraph、Tool、RAG 和持久化链路。
访客打开首页后会自动获得十分钟沙盒身份，然后可以体验四种有代表性的行为：

* 订单查询：看到规划器如何选择只读工具，以及身份如何绑定到工具参数；
* 售后问答：看到 Qdrant 与 BM25 两路召回、RRF 融合、引用和有据回答；
* 退货申请：看到写操作先生成草案、创建 Checkpoint、暂停审批，再恢复执行；
* 敏感问题：看到系统识别范围漂移和提示词泄漏请求，并走安全出口。

为什么不要求访客粘贴四枚 JWT
====================================================================================================

本地教学时，customer、reviewer、auditor 和 developer 分开，可以清楚演示企业职责分离。
但公网作品页的第一目标是让招聘者在几十秒内看到效果。如果先要求执行脚本和复制四枚 Token，
大多数访客会在真正运行 Agent 前离开。

因此公网模式增加了 ``public_demo`` 沙盒角色。它不是免认证：后端仍签发并验证 JWT，只是把登录动作
压缩成页面启动时的一次短时会话申请。审批、审计和调试接口还会检查目标 Checkpoint 的 ``user_id``，
确保访客只能操作自己刚创建的线程。

数据怎么隔离
====================================================================================================

每次打开页面都会获得一个不可预测的 ``demo-...`` 主体。订单仓库只把 ``user-001`` 的两条公开样例
映射给该主体，并返回归属于本次主体的领域对象副本。这样所有人都能演示同一订单号，但每个人创建的
退货记录、LangGraph 线程、审批恢复和审计查询仍以独立主体隔离。

可以把它理解成展厅里的样板车：每位访客都能试同一车型，但拿到的是自己的试驾钥匙，不能打开旁边
访客正在使用的车辆。

费用和滥用控制
====================================================================================================

* 默认使用 ``mock + hash + extractive``，不产生千问费用；
* 若公网模式连接真实聊天模型但没有显式允许付费，应用会在启动时失败；
* 匿名消息最多 500 字；
* Nginx 限制会话签发频率、业务请求频率和同时连接数；
* FastAPI 通过有限工位和短排队超时继续保护单个实例；
* Token 默认十分钟到期，只放在 JavaScript 内存，刷新后不会从浏览器磁盘恢复。

面试时怎么讲
====================================================================================================

不要只说“我把项目部署到了云服务器”。更有价值的说法是：

   原控制台需要手工配置四种 JWT，适合开发教学但不适合招聘者快速体验。我增加了短时沙盒身份，
   保留同一套受保护 API，并在审批、审计和 Checkpoint 路由增加线程归属检查。为了避免公开链接消耗
   模型余额，我把离线确定性链路作为默认模式，并用启动校验阻止误配付费模型。这样把体验步骤降到
   “打开页面、点击场景”，同时没有把认证和数据隔离删掉。

部署和验收命令见仓库根目录的 ``docs/public-demo-deployment.md``。
